# 2026-09-24 — Public-evidence snapshot

## English

This snapshot establishes the public-evidence layer for the Jev Research Index. Papers, projects, and online materials remain separate collections with independent counts.

The initial seed counts below describe the first curated export; the later “Web-crawled catalogue restoration” section records the superseding scope used by the current manifest and generated site.

### Added

- Defined the canonical scope: Jev refers to TypeSafe AI’s System One typed probabilistic decision model.
- Added same-name exclusions for Japanese encephalitis virus and the Journal of Extracellular Vesicles.
- Preserved 12 arXiv papers and 17 software projects with canonical URLs, relationship labels, evidence notes, and verification dates (including the newly verified crash-narrative study and Visual-Jev repository).
- Added 13 public-material records covering the official announcement, a podcast interview, an independent field report, third-party tracking, an official X channel, selected X records, and public video demonstrations.
- Added bilingual titles and summaries where the source was primary or clearly attributable.
- Added generated Markdown tables to `README.md`; `npm run validate` now fails if the README catalogue and JSON snapshots diverge.
- Added a separate README review-queue table so unresolved TRAE AI and Xiaohongshu leads remain visible without being promoted to the main catalogue.
- Discovery-only directory batches are retained in audit data but excluded from the public catalogue, counts, downloads, and rendered tables.

### Evidence limits

- This is a dated seed snapshot, not a claim of complete internet coverage.
- X records that could not be fetched directly remain at probable evidence and retain the access limitation.
- GitHub stars, forks, issue counts, prices, and model versions are not stored as timeless facts; any later metric must include an `as_of` date and a source URL.
- A Xiaohongshu search lead and one unstable Chinese-language article remain in `data/pending_review.json`; neither is presented as an established record.

### Limited source fetches

- `source:typesafe-x`: the account-level page was available, but individual linked statuses were not consistently machine-readable.
- `source:x-matija-jev`: the original status was not directly machine-readable; the linked archive is retained as a secondary evidence source.
- These are record-level access limitations, not claims that the channels or posts do not exist; `state/last_run.json` therefore keeps `failedSources` empty.

### Maintenance

- `state/last_run.json` records the successful review window and sources checked.
- Future reviews should read the previous snapshot, preserve changes and exclusions, and run `npm run validate` before publication.
